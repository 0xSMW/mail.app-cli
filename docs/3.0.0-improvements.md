# mail-app-cli 3.0.0 improvements

Version 3.0.0 makes native Mail operations and local reads the default on macOS builds with cgo. Mail handles composition, delivery, and existing message actions, while the CLI reads complete cached content directly from disk. Exchange accounts gain complete mailbox search, more reliable move verification, Unicode attachment lookup, and saved-draft workflows. Explicit Gmail label changes use a connected Gmail account.

## Faster reads with less process overhead

The native backend sends typed Apple Events directly to Mail instead of starting a scripting process for each operation. Account discovery, mailbox metadata, message changes, composition, rules, and signatures use the native transport.

Local message lists and searches use embedded read-only SQLite. Complete cached MIME files supply message bodies, recipients, reply headers, and attachment bytes without asking Mail to render each body. This reduces the work needed for batch reads and attachment exports. Concurrent searches share a bounded reader pool, and cancellation stays isolated to the read being canceled.

If a body or attachment is incomplete or unavailable locally, the CLI retains its diagnostics and uses a scoped Mail read where supported. Missing content is never presented as a complete cached message.

## Exchange mailbox support

Search finds mail across Exchange Inbox and other non-empty folders using Mail's local mailbox identities. Explicit `Inbox` and `INBOX` scopes resolve consistently. If a mailbox cannot be searched, the CLI reports an incomplete result; `--allow-partial` exposes the successful results together with the failed scopes.

Archive and move confirmation survive Exchange assigning a new local ID or changing the stored message size. A matching RFC Message-ID is confirmed with the sender, subject, sent time, and account scope, so a size change alone no longer leaves an otherwise confirmed move unverified. Ambiguous or unavailable identities still require reconciliation.

Attachment exports recognize canonically equivalent Unicode filenames. Freshly saved draft attachments are read from the selected account's special Drafts mailbox, avoiding an ordinary same-named folder or a lagging index. Draft updates preserve existing file bytes while adding new files.

Mail-generated wrappers around plain draft text are supported only when the text and ordinary attachments can be reproduced safely. Custom formatting, unsupported inline content, signing, encryption, and reply-header reconstruction remain available for editing and sending in Mail.

## Native replies and forwards

Create replies, reply-all messages, and forwards from the CLI or the TUI with Mail's native message relationships.

```bash
mail-app-cli drafts create -a "Example Account" -m INBOX \
  --reply-to 100001 --reply-all \
  --to recipient@example.test --subject "Re: Example" \
  --body "Complete reply body"

mail-app-cli drafts create -a "Example Account" -m INBOX \
  --forward-of 100001 \
  --to recipient@example.test --subject "Fwd: Example" \
  --body-file ./forward.txt
```

The same threading flags are available on `send`. Use an explicit mailbox for the original message and supply the complete outgoing subject, body, and recipients. `--reply-all` requires `--reply-to`; `--reply-to` and `--forward-of` cannot be combined. These operations require the native backend.

## Gmail archive uses Mail's Archive action

Archiving from Gmail Inbox invokes Mail's Archive action. Moving a Gmail message to another mailbox can add a label while leaving it in Inbox, so ordinary moves retain their label behavior.

Archive confirmation checks source removal and destination membership. A synchronization request does not by itself establish completed server synchronization.

## Explicit Gmail labels

List Gmail labels, inspect a message's memberships, and add or remove Important or existing custom labels without moving the message. Archive continues to remove Inbox membership while preserving Important and custom labels.

Label changes support dry-run and durable receipts. A fresh Gmail read confirms the requested change; the result separately reports whether Mail has reflected it locally. Reconciliation checks a saved receipt without repeating the change. Labels that belong to other actions, such as read status, stars, Spam, and Trash, return specific capability guidance.

Connect Gmail through OAuth or import an existing authorized credential file. Credentials are stored in macOS Keychain. See [Gmail labels](gmail-labels.md) for setup and commands.

Use a stable signed build to retain Keychain access across updates. Routine credential reads report an access error when interaction is required, without opening a password dialog.

Removing a label does not guarantee that a message leaves a date-based Smart Mailbox such as Today. The CLI's Today count includes messages received today, including archived messages.

## Composition and attachment safeguards

Sender selection, account ownership, and recipients are checked before submission. Saved drafts retain their identity and attachment checks, and attachment exports preserve filename and byte integrity.

An uncertain send is not submitted again automatically. Submission acceptance remains separate from delivery. A stored draft's original is removed only through guarded cleanup after submission; rich or special-header drafts that cannot be reconstructed safely remain available in Mail.

## Clearer rule information

Recognized, unambiguous rule conditions use Mail's public names. A rule whose move destination is unavailable remains visible with an unavailable-mailbox action, rather than causing the entire rule list to fail. Permission and transport failures remain errors.

## Consistent CLI and TUI commands

The CLI and TUI keep the same commands, flags, output formats, and message workflows. Library callers can run independent CLI invocations without carrying account, mailbox, or output options from one invocation into the next.

## Backend selection and permissions

On macOS, builds with cgo select native automatically. Choose a backend explicitly when needed:

```bash
mail-app-cli --backend native doctor
mail-app-cli --backend legacy doctor
```

`MAIL_APP_CLI_BACKEND=legacy` selects the compatibility backend for subsequent commands. `--backend auto` selects native when compiled; builds made with `CGO_ENABLED=0` select legacy. A failed native operation never automatically replays through legacy scripting.

The app launching the CLI needs Mail Automation permission for Mail operations and Full Disk Access for the local Envelope Index and MIME files. Gmail Inbox archive also requires Accessibility access. Run `doctor` to see which access is available; building or starting the binary does not grant those permissions.

Native source builds require Xcode Command Line Tools and cgo. The Go module path is now `github.com/0xSMW/mail.app-cli/v3`; library users should update imports from `/v2` to `/v3`. The CLI reports `3.0.0`, while the JSON output schema remains version 1.
